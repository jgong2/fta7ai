我们的架构设计

审核流程 · 主体已建

把审核流程拆成固定步骤

审核按固定步骤进行。只有一步交给大模型（LLM）给出建议，其余步骤由程序核对引文、给出判定。原则是：AI 提建议，程序做裁决。已建：判据规则（12 条）、报告生成器、标准资料接入层。

Ingest 读入工厂文件切成片段，每段记录出处
↓
Criteria 判据匹配按条款和工艺查判据表
↓
Evaluate · 唯一的 LLM 节点阅读证据，给出建议判定和引文
↓
Exit Gate 出口闸代码核对引文；证据不足时判为「待现场确认」
↓
Report 报告每条结论可追溯到原文页码
↺ 计划中：专家修改判定 → 存为样本 → 进入评估集 → 继续优化
多模型分工 · 已在使用

按难度和成本分配模型

难度高的判断交给 Claude 等前沿模型；批量、低难度的工作交给通义千问 Qwen、DeepSeek 等模型。模型可以替换，调度层自己维护。

DSPy 提示词优化 · 计划中

用专家样本持续优化

计划用 DSPy 把提示词（prompt）当作可优化的参数：给定评分函数和一批专家改过的样本，自动寻找效果更好的写法。评分规则重罚漏掉真实问题，鼓励在证据不足时如实标注「待现场确认」。

HOW WE WORK TOGETHER

合作方式

我们找的是项目合作伙伴（partner），适合独立开发者或两三人的小团队。FTA 提供真实问题、行业知识和客户场景；合作伙伴负责技术实现。

三个合作方向

来料检验 Agent · Incoming Inspection读取检验记录和图纸要求，标出超差项和缺失的证据。
整改验证 Agent · CAPA Verification判断整改是否真正关闭，并给出证据链和可信度。
供应商评估 Agent · Supplier Survey & Audit把供应商问卷、考核和现场审核证据串成一条线。

合作条款

  • 按交付成果合作，方式可以是股权（equity）或收入分成（revenue share），具体条款书面约定。
  • 远程为主，异步沟通，会议尽量少。
  • 有资深质量工程师一对一讲解业务，使用脱敏的真实案例。
  • FTA 不向合作方收取任何费用，也不要求购买任何课程或工具。
  • 作品可以署合作方的名字公开展示。

适合的背景

  • 工科背景，熟悉 Python，调用过至少一个大模型 API
  • 对 LangGraph、多智能体、DSPy 有兴趣，没做过可以边做边学
  • 有质量、制造或供应链背景更好
